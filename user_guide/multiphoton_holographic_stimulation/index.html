Multiphoton Holographic Stimulation (SysCon2 Export)

NeuroSeq can export stimulation patterns as SysCon2 .seq files for use with Holo4D multiphoton holographic stimulation hardware.

Overview

The stim array you draw in NeuroSeq represents laser TTL pulses directly. Each sample corresponds to one SysCon2 hardware tick (dt = 0.0005208125 s = 520.8125 µs). NeuroSeq infers the SLM shape objects needed for each neuron from the drawn TTL pulse positions — you do not need to manually define hologram boundaries.

Required setup

Parameter Required value
stim_array.dt 0.0005208125 s (one SysCon2 tick)
Cellpose segmentation loaded and mapped to stimulus channels
SysCon2 template a previously imported .seq file in the same session

The dialog will reject (or offer to fix) stim arrays whose dt does not match the SysCon2 tick quantum.

Drawing TTL pulses

Draw active samples in the stimulation editor exactly where you want the laser to fire. A few rules apply:

  • No minimum duration: pulses can be as short as one tick (520.8 µs).
  • dt must be the SysCon2 tick: use the Fix dt button in the sanity-check dialog if you need to convert an existing array.
  • Blank lead-in required: the SLM hardware needs one full 16.666 ms window (32 ticks) of blank time before the first laser pulse to load the hologram. The sanity fixer inserts this automatically if it is missing, but you can also add it yourself with Shift right for initial SLM load.

How shape objects are derived

The export pipeline maps your raw TTL pulses onto SLM shape objects as follows:

  1. Window coverage — each raw pulse is mapped to the 32-tick window(s) it falls in. This determines which SLM pattern windows must be loaded.
  2. Hologram grouping — active windows are grouped into holograms. A new hologram starts when the active neuron set changes relative to the previous non-empty window: either a neuron disappears or a new neuron appears. Gaps (fully empty windows) do not break the hologram — the pattern stays loaded across the gap.
  3. Pre-load blank window — a blank 16.666 ms window is placed immediately before the first active window of each hologram. The SLM uses this time to load the pattern before any laser pulse fires. If the blank is missing the sanitizer inserts one by shifting the tail right.
  4. Shape object bounds — for each neuron within a hologram:
  5. shape starts at (first_active_window - 1) × 32 ticks (the blank load window),
  6. shape ends at last_active_window_excl × 32 ticks (minimum span: load + 1 active window).

TTL pulse timing

Laser TTL pulses are emitted at exact tick positions, not at window boundaries. If a pulse was drawn at tick 100, the exported .seq file contains a TTLPulse starting at tick 100 (= 52.08 ms).

If the sanitizer inserted a blank window before the first active window (because the first pulse was too early), all raw pulse positions are shifted by 32 ticks per inserted blank. The shift preserves the sub-window offset of each drawn pulse relative to its containing window.

Roundtrip accuracy — when a .seq file exported in this mode is imported back into NeuroSeq with dt = 0.0005208125 s, each pulse reconstructs at the same sample index it was exported from (sample_idx == tick_idx).

Hologram boundary rule

Situation Effect
Same neuron set, contiguous windows continue same hologram
Same neuron set, gap between windows continue same hologram (SLM stays loaded)
A neuron that was active in the last non-empty window disappears start new hologram
A neuron that was never in the current hologram appears start new hologram

A new hologram is triggered whenever the active neuron set changes — either a neuron leaves or a new one joins relative to the last non-empty window. Gaps (fully empty windows) are ignored when checking for disappearances; only transitions between consecutive non-empty windows matter.

Sanity checks

Run Check Input Sanity in the stimulation generator dialog before exporting. The checker validates:

  • dt is the SysCon2 tick quantum (offers Fix dt button if not),
  • first active sample is at least 32 ticks from the start (SLM lead-in),
  • no SLM gap violations between successive neuron groups,
  • no off→on SLM overlap violations,
  • no simultaneous neurons with mismatched durations (optional; use Equalize durations),
  • all active neurons have a valid Cellpose mapping.

Feedback is shown in a scrollable dialog. If fixes were applied you can write the corrected values back to the stim array via Apply fixes.

Exporting

  1. Open File → Export → Optogenetic Input and choose SysCon2 in the pre-dialog. This writes the files only; to also import the generated sequence into a connected SysCon2, use Export with settings… in the Stimulation setup panel instead.
  2. Select the stim array and Cellpose segmentation.
  3. Choose laser wavelength (940 nm, 1030 nm, or 1100 nm digital; default 940 nm).
  4. Optionally set a Target power and load a power LUT (see below).
  5. Click Check Input Sanity and resolve any errors.
  6. Enter an output script name and click Export.

The output folder starts as the one used last, or Documents\NeuroSeq\SysCon exports the first time, so scripts can be generated without browsing for a folder. Scripts imported into SysCon2 go to its Target directory, which defaults to one folder per day, neuroseq\<date> (e.g. neuroseq\2026-10-15).

In the SysCon2 panel, the Target power box next to Export current array to stimulation setup sets the power of that quick export. Changing only the power there keeps all other settings of the last export; Export with settings… starts from the same value.

Export settings and the export folder belong to the project: they are saved with it and restored when you switch between open projects.

Target power and power LUT

The dialog has a Target power (mW) spinner next to a Load LUT… button:

  • Setting Target power to 0 disables power control — the exported Intensity_0 fields are written as zero, which matches the historical default behaviour.
  • Loading a SysCon .lut file maps the requested mW to the laser's intensity percentage at the currently selected wavelength. The exporter divides that percentage by 100 for the .seq intensity fields (0–1). Each wavelength has its own LUT slot. The mW those fractions stand for are kept in each Shape's and laser pulse's description, e.g. neuron=3 power_mW=12.5 target_mW=25 (the requested power for that object, i.e. the target times its amplitude, and the target power).
  • LUTs are bundled into the .nseq archive when you save the project, so the export stays reproducible across machines. Loading a LUT marks the project as modified; save it to retain the calibration.

The status label next to the button shows which LUT (if any) is currently loaded for the active wavelength. Switching the wavelength combobox swaps to that wavelength's LUT slot.

The exporter writes:

File Content
<name>.seq SysCon2 sequence — Shape objects + TTLPulse objects
<name>_original_stim.npz the exported input array, restored on re-import
<name>_overview.png timeline overview image

Importing a .seq file

Use File → Import data → Input → Optogenetics to reconstruct a sequence in a new or existing input array. Browsing and cancelling do not change the project. Import applies the file's header as the session's export template only after conversion succeeds. The imported input uses 520.8125 µs samples. If an existing target input uses a different interval, only that input is resampled after confirmation. Other input arrays and trace datasets keep their own intervals and align by time in the plots.

Targets map to consecutive channels starting at Target neuron offset, in their first-occurrence order for Holo4D sequences. They are not matched to project neuron IDs or Cellpose identities. Repeated point Shapes at identical coordinates and with the same lightsource share a channel; nearby legacy Entities retain the 1 µm grouping rule. Multiple spots in one ROI may therefore import as separate channels. The preview shows the same grouping used for conversion.

Replace mapped target channels clears only channels receiving imported data; other channels are preserved. Disable it to merge using the maximum value at each sample. Dropped channels, clipped duration, and capped legacy repeats require confirmation before the project changes. Files that reconstruct no stimulation are rejected, as are arrays exceeding the 512 MiB import allocation limit.

Holo4D timing is reconstructed from each target's laser TTL pulses and SLM availability windows. The Legacy repeat tick setting does not change Holo4D's 520.8125 µs TTL quantum. One sequence pass is imported; the header's runs count is not expanded. Imported amplitudes are raw file intensity values, with a nominal 1 used for zero-intensity shapes, rather than recovered optical power or the original drawing amplitudes. Spiralling latency and hardware behavior cannot be inferred from the file, so this is not a measurement of delivered stimulation. Objects with multiple timing entries or multiple lightsources are rejected rather than partially imported.

Every export also writes <name>_original_stim.npz next to the .seq: the exact input array, including silent neurons. The .seq holds hardware-adjusted timings (SLM load delays), so importing it alone reproduces those adjusted timings. When the sidecar sits next to the file and still matches it, the import restores the original array with its exact timings and neuron rows. Keep the two files together.

Setup panel and hardware execution

Export defaults are 940 nm, Force binary export intensity off, Spiralling off, Exact stimulus timing on, and Use 10 input spots per ROI on. With exact timing, each hologram shape starts one 16.7 ms SLM load window before its first pulse instead of on the window grid, and stimuli are delayed only where the previous hologram leaves no room for that load (the first stimulus is always delayed by one window). Untick it to snap shapes to the window grid, which can delay stimuli by up to a window per hologram. Previously remembered settings still apply to quick exports. With a linear 85 mW maximum calibration, 5 mW is exported as approximately 0.058824, not 5.8824, in both Shape and laser TTL intensity fields. Use the rig's measured wavelength-specific LUT; the linear example is not a replacement calibration.

Main-menu exports populate the setup panel's generated preview without importing into hardware. Exports from the setup panel import when connected. Routine blocks also update the preview after import acknowledgement. Preview images resize with the panel and remain distinct from hardware status.

Laser controls are currently read-only: Get Status discovers lightsources on its first use, preferring 940 nm, and retrieves status. The single selector displays friendly names while retaining the original SCI identifiers internally. Set power, shutter, and emission in SysCon2 itself.

Select the imported sequence, choose Runs and trigger settings, and click Upload. After confirmation of an endless upload, NeuroSeq uploads and waits for hardware Idle. Then click Run and confirm to start the sequence. The panel shows phases, elapsed time, and hardware Busy/Idle state; SCI provides no percentage-complete measurement. A triggered run remains waiting until Busy is observed. A short automatic run can finish between polls; that case is reported without claiming measured completion. Stop also cancels any queued Run.

The preview is collapsed by default; click Show preview to expand it.

The dynamic-routine dialogs offer Use SysCon2 dt and prompt for resampling when starting with the wrong timestep.

Dynamic input routines on the rig

With the SysCon2 (calcium imaging) target, the rheobase and STDP window dialogs show Hardware settings: target power, laser, spiral scanning and spots per cell (the project's export settings, shared with the SysCon2 tab, so no Export with settings… is needed first), plus how blocks are recorded. With Run blocks automatically and record them with ScanImage, each block is uploaded and run by NeuroSeq while ScanImage records it, triggered by the sequence, and its ΔF/F traces are extracted with the project's Cellpose masks; see ScanImage acquisition. Rheobase then counts a probe as evoking a response, depending on Calcium readout, when the neuron's ΔF/F rises by the Response threshold within the post-pulse window, or when OASIS deconvolution of that ΔF/F finds a spike (an event of at least the Spike threshold) in it. Unticked, each block is only imported into SysCon2 and you run, record and import it yourself, then click Calcium data imported (rheobase can then measure the rise of an imported ΔF/F or raw fluorescence trace, e.g. the TIFF import's ROI averages, or deconvolved spikes; Suite2p's normalised traces are refused, since a rise relative to their baseline is meaningless). Export warnings are asked once per routine rather than failing every block. Since probe amplitudes are fractions of the target power, a routine refuses to send a block without a target power above 0 mW and a power LUT for the chosen laser, or with a target above the LUT's maximum (higher amplitudes would all be delivered at that maximum); every stimulated neuron must have a Cellpose ROI. Amplitudes must be above 0 and at most 1.

Choosing the SysCon2 target first gives rheobase settings for cells in a slice: a 16.7 ms pulse (one spiral; a shorter pulse with spiral scanning on is logged as a warning, since only part of the spiral is delivered), up to 100 ms, 1 s recovery, a 300 ms post-pulse window and Fixed duration, varying amplitude, since every probe is a recording. Each target keeps its own values when you switch back and forth. With deconvolved spikes, a spike in the imaging frame after the post-pulse window still counts: the frames lit by a short pulse are imputed, so its response first shows in full in the next frame. Simulations finishing or failing meanwhile do not affect a hardware run.

Each routine run keeps its block scripts in its own folder inside the project's export folder (the one Export with settings… used last), for example SysCon exports\rheobase_2026-10-22_143012\. Every block is saved there as rheobase_2026-10-22_143012_001.seq, with its overview PNG and stimulus sidecar, and imported into SysCon2 under the same name, so names never repeat across runs. A recording of a block records the path of its .seq. Scripts exported with Export current array to stimulation setup stay temporary and are deleted when NeuroSeq closes. The Create input array and Edit input array dialogs also provide exact presets for SysCon2 (520.8125 µs), 1 ms, 0.1 ms, 50 µs, and 30 Hz imaging.
